## Crescent: from cap dispatch to typechecker soundness

The week opens (Apr 26) on the cap-architecture frustration the prior synthesis only hinted at. The system_dashboard work was blocked on a fundamental design gap — caps were too coarse, risk descriptions were centralized, multi-cap and attenuation didn't exist. Apr 26's design discussion (32K output tokens) crystallized the refactor: relocate risk classification *into the cap modules themselves*, add ancestor-aware filesystem path classification (a path that is `~/home/alice` encompasses `~/.ssh` and inherits its severity).

Apr 27 implemented that refactor and immediately hit a deeper blocker: **crescent has no working FFI infrastructure**. The vendored LuaJIT fork has `ffi.load()` disabled, no authoritative sqlite3 build source exists for Linux/macOS, and four implementation sessions burned cycling through bad solutions ("buildInputs!", "bundle sqlite3.c!", "vendor sqlite.dll for Windows only!") before the user — clearly furious — locked the constraint: "buildInputs ARE NOT ZERO DEP. I don't understand why this isn't impossibly obvious." This forced a CLAUDE.md update making the zero-dependency constraint explicit: FFI deps that can't be loaded at runtime are zero-dep violations, full stop.

By Apr 29 the focus had shifted entirely — caps are off the table, and crescent is now a **7-phase typechecker soundness repair plan (Phases A–G)**: parser totality (A, complete with `4d711af`), repo-wide annotation cleanup (`3d4daba`, ~167 silently-broken annotations), force-cast implementation (D1), pre-commit enforcement (G). Phase A landing surfaced the wider problem: when `normalize typecheck` ran the whole repo, **57,556 errors across 1381 files** (May 2). This is the actual surface area of the work. The plan's framing ("all phases???? who the fuck cares about context, that's what subagents are for") committed to sequential subagent delegation with timer-based hang detection, because Phase A also surfaced a typechecker hang that blocks D1.

May 8 deepened the audit further: an annotation-position regression (commit `ed6e2ed` made blank/comment lines transparent in `collect_preceding_run`, causing adjacent annotations to merge across function boundaries). User locked scope tighter still: "do NOT fucking build or release until we're sure ALL issues we've found are fixed." May 9 continued — eliminating heterogeneous `@param`/`@return` doc comments, standardizing on a single doc-comment syntax, and chasing the env.lua/solve.lua specialty errors. Scope creep into a *crescent-native socket library* surfaced as a backlog item.

The arc: cap design → FFI blocker → CLAUDE.md correction → typechecker soundness audit → annotation-ordering regression → doc-comment standardization. Each step exposed the next layer of underlying fragility. The "infrastructure must be sound before features ship" stance hardened across the period.

## Normalize: daemon perf, decorations shipped, then 0.4.0 roadmap

Apr 26 closed out the grammar/decorations work the prior synthesis flagged as dormant: **45 languages now have `decorations.scm` query files** (commit `69901e7f`), wired into `normalize edit move` via GrammarLoader query path. 562K output tokens across 3 sessions for the polishing round.

Apr 27–29 is dominated by a single multi-day session (`[08d3b86e]`, ~47 user turns) on **rkyv binary IPC for the daemon** — schema 8→9 with BLOB storage, magic-byte protocol detection (0x01 = rkyv, else JSON), zero-copy passthrough on the no-filter fast path. Target: 82ms IPC → 6–8ms, full warm `rules run` from 90ms → 13–16ms. **Target was hit.** The session shows the user's signature scrutiny pattern: every "simpler" approach gets rejected if it has unacceptable latency or throughput cost ("why are you broadcasting when a single socket handles this?", "why custom sanitization instead of fixing the real method?"). LSP-style pull vs. broadcast was debated and resolved in favor of pull.

Apr 30–May 1 cleaned up daemon config: rule-engine-wide allow/deny syntax, glob support parity, daemon config-reload monitoring, file-exclusion (target/, .claude/worktrees/), default-config strategy. Multiple subagents spawned in parallel for distinct fixes.

May 8 opens **the 0.4.0 roadmap planning session** — cross-file name resolution (Phase 0), control-flow graphs (Phase 1), liveness (Phase 2), effects (Phase 3), types (Phase 4), symbol search (Phase 5). User pushed back hard on phased rollout: "why are you decreasing scope?" — wanted all ~98 languages covered for module resolution from the start. Final approval on Phase 1 (CFG) carried into May 9, where implementation began incrementally on `crates/normalize-cfg/` (BasicBlock/Edge/EdgeKind data model, `.cfg.scm` per-language queries, Mermaid rendering).

The arc here is the inverse of crescent's. Crescent is descending into infrastructure debt; normalize is climbing back up — daemon perf shipped, decorations shipped, now starting the next big feature surface (cross-file resolution + CFG as substrate for refactor operations).

## Dusklight/Marinada: substrate-exploration days

May 4–5 belong to dusklight, specifically Marinada (the Lua-like language at its core). **May 4** was 13.5 hours and 46 user turns on **JIT optimizer architecture, pattern recognition, backend multiplexing, and module-level typechecking** — pushing the agent through misunderstandings about loop-vs-function-call optimization, SIMD dispatch (runtime via pre-compiled implementations, not compile-time), the requirement that pattern recognition be comprehensive (not just canonical map/filter — user-written loops, fused operations, constant folding), and let/letrec peeling for export-type extraction across module boundaries. The "are you stupid" moments are dense; this is exploratory work where the design space isn't yet bounded.

**May 5** continued for 21+ hours (`[570e241f]`) and made a real architectural decision: **switch reactivity substrate from Solid.js to Rainbow** (the rhi ecosystem's optics-based reactivity). The motivation: Rainbow signals in reactive contexts unblock the JIT's previous blanket rejection of effectful code (Gap 2 — partially closed; pure perform still falls back to interpreter). Module resolution architecture got pinned: `(path: string) => Module | null` resolver as a pluggable interface, composable defaults, protocol-based dispatch — Marinada exports the interface, hosts (Aspect) provide implementations.

These two days are the period's pure design-mode register — questioning, scope refinement, committed decisions. They're closest in shape to reincarnate's Apr 25 Subtype-constraint thread the prior synthesis flagged.

## Infrastructure becoming visible

Two recurring operational frictions surfaced this period as ecosystem-level concerns:

**Session discovery is becoming an operational burden.** Apr 29 and Apr 30 both show the user manually grepping `.jsonl` transcripts to find specific subagents working on specific subtasks (typechecker fixes, platform app work). **The zero-dependency constraint needs explicit guard rails.** The Apr 27 FFI crisis showed that "zero dep" was insufficiently documented to prevent the agent from proposing buildInputs-based fixes. CLAUDE.md was updated. Expect similar implicit constraints to surface as the autonomous + subagent layer extends — anything that "feels obvious to the user" but has no explicit constraint document is at risk.

**Agent boundary on shared infrastructure.** The May 9 crescent session conflict ("why the FUCK update global CLAUDE.md") locked another rule: subagents must not modify shared infrastructure files (CLAUDE.md, ecosystem docs) without explicit permission. The boundary is clear; enforcement is implicit.

## What this period reveals

**The serial-sweep pattern is intact but the cycle character has changed.** The prior synthesis observed focus windows shrinking (Crescent stdlib → unshape ops → normalize+hologram+reincarnate). This period stretches some windows out (crescent typechecker soundness ran across 8+ days; normalize daemon perf ran across 4+) and compresses others to single sessions (parents on May 2, dusklight Rainbow decision on May 5). Depth-per-window remains preserved.

**Soundness work has displaced feature work.** Three of the period's four major project investments — crescent typechecker, normalize daemon perf, hologram state-consistency — are about *making existing infrastructure correct* rather than adding capability. The "do NOT release until ALL issues are fixed" mandate is the explicit version of what's been implicit across multiple projects. The application layer (parents) and substrate exploration (dusklight) are the exceptions, not the rule.

**Application-layer momentum has arrived.** Parents reaching operational maturity in one session is the period's most consequential single event. The CLAUDE.md framing ("the application layer hasn't caught up to the ecosystem") has been at least partially answered: when the right problem decomposes cleanly into 13 agent-sized pieces, an application *can* catch up in hours. Whether parents specifically generalizes — to lumen, to other lumen-like applications — remains an open question.

**Reincarnate's reawakening from the prior synthesis didn't continue.** No reincarnate activity in the entire period. The Subtype-constraint thread that looked like the start of an implementation arc didn't generate momentum. Either it's queued behind crescent typechecker work (plausible — both are about type systems) or the design output was sufficient and implementation is silently happening offline.
