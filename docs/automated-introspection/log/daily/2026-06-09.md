### github-io (fuwafuwa cost analysis + remediation plan)

Two user-directed sessions, both focused on understanding and fixing fuwafuwa's quota burn.

**Session [ebc767df] — cost analysis:**
- User opened with: "can we analyze quota usage by repo since last saturday (6th?)"
- Subagents read raw session logs across the 2026-06-06..09 window and produced a cost-weighted breakdown.
- Discovery: fuwafuwa had consumed ~$300 of a ~$305 window's quota — nearly the entire budget — delivering only 9 actual Discord messages out of ~831 sessions. 98.9% of sessions spawned a full Opus session, decided there was nothing to say, and exited.
- User: "fuck :/ we need to figure out why fuwafuwa has 10m input tokens and 5m output"
- Root cause identified: the heartbeat pre-check spawns a full Opus session for ANY new Discord message in ~13 channels, then uses that expensive session purely to decide whether to engage. The engagement gate was the session itself, not a cheap filter before it.
- Secondary issue surfaced: `#Neona-X` had been asked to be unsubscribed 2026-06-01, patched with `gateIgnore:true`, but `gateIgnore` was not honored in the pre-check, so spawns continued.
- User: "yes please. as much as i love how interactive fuwafuwa is, it's not feasible to keep her running so interactively. also we need anti-looping measures for fuwafuwa specifically"
- Output: a complete multi-tier remediation plan (20KB+ spec), covering: (1) a cheap Haiku triage gate replacing the Opus engagement decision; (2) a real `unsubscribe` mechanism with a `leave` Discord subcommand; (3) anti-loop guardrails (hard caps, circuit breaker, debounce, heartbeat interval increase).
- Closing: "... alright, fine, keep + fix." — user approved the plan after reviewing tradeoffs.

**Session [a13a538a] — implementation:**
- Full implementation of the remediation plan from session [ebc767df], executed on the fuwafuwa repo.
- Tier 1: `--json` mode added to `discord.ts` `messages()` and `dm()` for cheap pre-filter reads; heartbeat's channel loop replaced with an accumulating map; addressed-signal check (mentions, replies, name-mention) added for unconditional Opus spawn; ambient-only path now routes through a `claude-haiku-4-5 --bare` triage call ("Would fuwafuwa naturally want to chime in? Answer yes or no").
- Tier 2: `leave` subcommand added to `discord.ts`; `#Neona-X` left and marked `unsubscribed:true` in `brain/discord-channels.json`; pre-check loop updated to honor `unsubscribed` and `gateIgnore`.
- Tier 3: `brain/rate-limit.json` scaffolded; hard caps (6/hr, 50/day) and circuit breaker (5 spawns in 30min → 1hr cooldown) added to heartbeat; heartbeat timer interval increased.
- Committed as `5d6cc025` (rate-limit scaffolding), `6271b9d5` (CLAUDE.md rewrite), `b17e461a` (full implementation).

**Observations:**
- This is a clean example of the "LLM as oracle at the leaves" principle applied self-referentially: the Opus engagement loop was replaced with a deterministic accumulator + cheap Haiku oracle at the single decision point where model judgment is actually needed.
- The analysis revealed that 6 of 9 real messages were proactive ambient chimes — exactly the behavior worth preserving. The triage gate is calibrated to retain that while eliminating the 98.9% null-spawn majority.
- The `gateIgnore`-doesn't-stop-spawns defect had been silently running for 8+ days after the original unsubscribe request — a latent bug surfaced by cost data, not by behavior.
