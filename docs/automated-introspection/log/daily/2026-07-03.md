### hologram (exoplace Discord bot)

User-reported regression: `/trigger` was working, but mention-handling and random-reply features were broken. The session diagnosed the root cause in 2–3 turns: Discordeno's REST manager has no request timeout, so a single black-holed connection wedges its serial-per-route queue forever, hanging the message path's REST awaits (deputy check, channel/guild metadata) until the 120s channel-queue timeout kills each task, while `/trigger` (stub metadata, webhook-token routes) kept working.

**Fix committed:**
- New `rest-timeout.ts` module wrapping Discordeno's REST manager to attach an `AbortSignal.timeout(...)` to every outgoing request (30s default, 60s for file uploads). No node_modules patching required — the hook point is `createRequestBody`.
- Updated `client.ts` to install the timeout wrapper immediately after `createBot`, plus two `if (signal.aborted) return;` guards so tasks whose queue slots are reclaimed unwind instead of responding orphaned.
- New `rest-timeout.test.ts` with 4 tests (signal attachment, per-request freshness, upload timeout, end-to-end with a never-responding server).
- Updated `TODO.md` with notes on unpinned discordeno drift and `LOG_LEVEL=debug` verbosity in production.

**Observations:** This is a clean fix for a real availability bug — a hung connection cascading through a serial queue. The diagnosis was fast and the fix is minimal (single module, two guard statements).
