**Activity:** Extended session investigating and implementing infrastructure improvements for vendored C dependencies. Work spanned three main areas: confirming current vendoring status of LuaJIT and tinycc, analyzing CI storage patterns and artifact lifecycle, and implementing version pinning + skip-build logic to reduce unnecessary CI runs. Later pivoted to vendoring TinyCC itself as a fallback build tier, including SHA pinning for both TinyCC (mob branch) and LuaJIT (moved from floating v2.1 ref to a pinned commit).

**Key outcomes:**
1. **Version pinning and skip-build** - Added per-dependency version-check job to avoid redundant builds when upstream deps haven't changed
2. **Artifact retention** - Trimmed artifact retention from default 90 days to 1 day to reduce storage overhead
3. **TinyCC vendoring** - Vendored TinyCC mob branch as Tier 4 fallback compiler, with LGPL-2.1 license documented
4. **LuaJIT SHA pinning** - Re-pinned floating v2.1 reference to specific commit across all five build jobs
5. **Gap analysis** - Identified and documented that TinyCC cannot yet build LuaJIT (assembler limitation with sym@PLT), sqlite3/zlib build cleanly, and evaluated effort for fixing asm support (small, surgical patch needed)

**Research findings:**
- LuaJIT is fully vendored as prebuilt binaries; source is fetched fresh in CI but never committed
- CI artifact storage is used only for transient cross-job hand-off within a single workflow run, not as persistent storage
- No redundancy between artifact storage and git commits; builds happen unconditionally on every run (now with optional skip via version-check)
- libressl uses full autotools build with assembly enabled by default on Linux x86_64 (60 assembly source files)
- TinyCC's assembler gap for luajit is a parser omission rather than architectural (sym@PLT syntax), plausible to fix in a fork
