### mycelium

Three extended sessions continuing distribution architecture exploration. Earlier context: deciding between JVM modes (native-image 10ms startup/no JIT vs JDK 4-5s startup/full JIT).

**Session 1 (handoff start 09:42:21)** — Explored split language JAR architecture. Task agents completed:
- **"JVM mode with split language JARs"**: Moved language implementations (GraalJS, Ruby, Python, LLVM, Wasm) from `implementation` to `compileOnly` dependencies, created separate `jsLang` configuration alongside existing language packs. Core size dropped to 22MB (from 709MB with all languages). Default jvmRun still works unchanged; `-Planguages=js,ruby,python` syntax allows arbitrary combinations. All tests pass.

**Session 2 (handoff start 09:42:21, same session)** — Memory reclamation testing on GraalVM CE 25.0.2.
- **"JVM memory reclaim test"**: Built memory-load test allocating 250k objects with string/nested fields, running 20 churn cycles, then idling 65 seconds. Tested three GC configs: default G1 holds ~28% reclaim (2195→1576MB, then flat), G1 + tuned flags (`G1PeriodicGCInterval=1000`, `MinHeapFreeRatio=10`, `MaxHeapFreeRatio=20`) achieves 90% reclaim (2195→187MB in 30s), ZGC partial reclaim (slower, less complete than tuned G1).

**Session 3 (same window)** — Discovered and fixed critical setTimeout bug.
- **"Fix setTimeout event loop"**: Previous implementation spawned a background Thread per timer, which crashed on re-entry to GraalJS's single-threaded Context (`IllegalStateException: Multi threaded access`). New `TimerManager` (host-side, single-threaded) manages timers in a `LinkedHashMap`, runs callbacks on the calling thread via `runEventLoop()`, and properly exits when only unref'd timers remain. Tests rewrit to exercise deterministic timer behavior, `ref()`/`unref()`, nested setTimeout. Verified end-to-end with real CLI — no threading crashes, clean process exit in <1s when appropriate.

**Highlight**: setTimeout was "frankly unacceptable" when broken; fix enables any user script doing `await sleep(ms)` at top level.
