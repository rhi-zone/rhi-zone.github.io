- Direct tree-walk dispatch via `candidatesForUrl` replacing `buildRoutes`/`Route[]`

This task was substantial — ~1.77M milliseconds (~30 minutes of compute) — and landed with commit `7d50b9e`.

**Phase 3: Prior-art research (08:44–09:36)**
Four parallel agents researched effect systems and multi-transport routing frameworks to inform the cross-cutting/caller-context layer design:
- **Effect-TS**: Layer/Service pattern, context flow via type-level `R` union, middleware as service transformations, multi-transport via Layers
- **tRPC**: Router/procedure definition, chainable `.use()` middleware with context merging, transport adapters, inspectable router definitions
- **Hono**: Koa-style onion middleware, generic context types, multi-runtime via Fetch API, decoupled OpenAPI registry
- **Elysia**: Method-chained routes, schema-first (TypeBox/Standard Schema), type-level context accumulation via Derive/Resolve, four-tier lifecycle phases

Findings written to `docs/design/prior-art/{effect,trpc,hono,elysia}.md`. Key insight: all systems cleanly separate transport surfaces from handler definitions via either Layers (Effect), Adapters (tRPC), or schema merging (Elysia/Hono).

**Phase 4: Unsettled questions (09:36–10:25)**
Returned to synthesis. Clarified that fractal solves the surface-projection half (one def → HTTP + CLI + MCP) but does not touch caller-context or cross-cutting concerns. Those remain orthogonal design problems requiring a separate solution. Discussion on whether TypeScript build-time metaprogramming (procedures as expressions) is sufficient without proc macros — deferred to next phase with recommendation to write settled items and handoff.
