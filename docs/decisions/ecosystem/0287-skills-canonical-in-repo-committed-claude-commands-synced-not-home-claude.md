# ADR-0287: Skills are canonical in each repo's committed .claude/commands/, fanned out by sync-skills.sh; never ~/.claude

- Status: Accepted
- Date: 2026-06-16

**Context.** ADR-0014 set the canonical skill location as `tooling/claude-commands/` in github-io with `~/.claude/commands/` symlinked to it, propagated via `propagate-skill.sh`. That mechanism was retired. A `~/.claude/commands/` entry is global-by-construction with personal-over-project precedence, so a single ecosystem skill placed there shadows the committed copy of *every* repo opened on the machine — not just github-io's. The symlink layer also meant github-io's own harness load path was a home-dir indirection rather than its own versioned files. A correctness fix was needed that keeps skills versioned, per-repo, and free of any global shadow.

**Decision.** This supersedes ADR-0014. The canonical skill location is each repo's own committed `.claude/commands/*.md`, loaded directly at project scope. github-io's committed `.claude/commands/` is simultaneously the ecosystem's authoring source of truth and github-io's own load path — one directory, two roles; github-io is not special, it loads its skills from committed in-repo files like every other recipient. Distribution is `tooling/sync-skills.sh`, which reads git-tracked bytes only from github-io's committed dir and fans them out to the recipients listed in `tooling/skill-recipients.txt` (the rhi-zone dev-substrate subset in `tooling/skill-recipients-rhizone.txt`, per-skill tier in `tooling/skill-tiers.txt`). It is idempotent and convergent, skips dirty receivers first (recording a TODO.md line rather than mutating a dirty tree), is non-destructive by default (orphans removed only under `--prune`), and exposes `--check` as a dry-run drift guard that exits non-zero for CI/`/loop`. The `tooling/claude-commands/` warehouse, the `propagate-skill.sh` script, and all `~/.claude` skill symlinks are removed.

**FORBIDDEN.** Never create a `~/.claude/commands/` or `~/.claude/skills/` entry for an ecosystem skill. `~/.claude` is global with personal-over-project precedence, so one such entry shadows the committed copy of every repo ever opened on the machine — exactly the defect this ADR removes.

**Alternatives rejected.**
- *Keep the in-repo canonical location but retain the `~/.claude` symlink (move only ADR-0014's source dir)* — Does not fix the root defect: any `~/.claude` skill entry is global with personal-over-project precedence and shadows every repo's committed copy. The symlink layer had to be removed entirely, not relocated.
- *Amend ADR-0014 in place* — Violates the append-only ADR convention (docs/decisions/README.md): an accepted decision is superseded by a later citing ADR, not edited away.

**Consequences.** Editing a committed skill in github-io's `.claude/commands/` is immediately live for github-io with no propagation step; other repos converge on the next `sync-skills.sh` run, and dirty receivers converge on their next clean run after their TODO.md note is cleared. The flat `.claude/commands/<name>.md` format is retained deliberately; the `.claude/commands/<name>.md` → `.claude/skills/<name>/SKILL.md` directory-per-skill migration is fenced as a separate later refactor to avoid a half-migrated mixed-format ecosystem. Authoritative mechanism description: the CLAUDE.md skill section and docs/artifacts/skill-loading-audit/synthesis.md.
