# ADR-0034: Don't hand-roll what a library does; use crates for standards

- Status: Accepted
- Date: 2026-05-29

**Context.** Repeated velocity-vs-architecture cycles produced hand-rolled implementations of standardized functionality that had to be torn out once the real scope of the underlying standard surfaced. Hologram built a custom template engine that was migrated to Nunjucks within days. Reincarnate's SugarCube frontend used a hand-rolled ~760-line Pratt parser and a hand-rolled HTML entity decoder; after multiple sessions debating whether to keep extending the bespoke parser, the parse-correctness ceiling forced a choice between continuing to grow custom code or adopting maintained libraries.

**Decision.** Prohibit reimplementing functionality that an established library/standard provides: prefer existing crates for standardized formats rather than hand-rolling. Encoded (Feb 17) as the CLAUDE.md behavioral rule "Don't hand-roll what a library does. Use crates for standards." The triggering migration replaced the hand-rolled Pratt parser with oxc_parser and the hand-rolled HTML entity decoder with the html-escape crate (full HTML5 spec).

**Alternatives rejected.**
- *Build/extend custom implementations of standardized functionality (custom template engine, hand-rolled Pratt parser, custom HTML entity decoder)* — Bespoke implementations repeatedly proved inadequate at the true scope of the standard and were torn out: Hologram's custom engine migrated to Nunjucks within days, and the ~760-line Pratt parser was replaced with oxc_parser after discovering the scope of SugarCube's actual semantics. The library migration drove parse errors from 974->0 (TRC) and 290->4 (DoL), and html-escape covers the full HTML5 entity set that bespoke code did not. Custom builds could not reach standards parity affordably, so the principle was promoted to a rule.

**Consequences.** Establishes a standing ecosystem-wide convention (captured in CLAUDE.md) to prefer maintained crates over bespoke implementations of standardized behavior. Future implementers must reach for established libraries first on standardized formats, constraining greenfield parser/engine choices across pipeline and runtime layers and reducing the velocity-vs-architecture rework cycle for well-trodden problems. The migration also forced discovery of SugarCube's actual semantics.
