# Synthesis: What is actually wrong

## Was the original framing right?

**No.** The user's presenting complaint — "Claude Code is performing worse" — is not supported by the evidence. H-MODEL-REGRESSION is dead: zero version-named complaints, every model switch is *toward* opus (an upgrade, not a retreat from a degraded model), and the cache-independent signals (tool errors, user affect, switch direction) all point the same way. The presenting example — crescent's typechecker "rewritten 3+ times" — turns out to be four architecturally-distinct generations (HM unification → constraint-based → two-phase → set-theoretic / MLstruct-style), with a clean-room rewrite design grounded in published literature (SimpleSub, MLstruct) and a May 18 retraction-under-challenge where the model correctly distilled a 51-invariant audit down to 6 fundamentals. That is shipped architectural evolution under high friction, not capability collapse. H-DESIGN-CEILING is dead.

The accurate reframe is: **the model is roughly fine. The transmission channel between the user's aesthetic and each fresh session is the bottleneck.** What looks like "performing worse" is the user paying recurring costs to push the same generator through CLAUDE.md, one violated rule at a time.

## What is actually wrong

**1. The implicit-constraint set is large, still being mined, and documented only post-violation (H-IMPLICIT-CONSTRAINTS — alive, strongest).** Five of six items survived red-team with the three-step chain verified at git-blame level: user surprise → constraint absent in pre-incident CLAUDE.md → same-day commit adds the exact rule. Canonical cases: buildInputs ≠ zero-dep (`514daf1a` → commit `de5859786`), copout/minimal-change ban (`d4565916` → `57a4be65`), subagent hard-scope (`9501a0b0` → `9fd4b560`), memory-system hardening (`9501a0b0` → `aa87bca5`). Load-bearing meta-evidence: crescent committed 98 CLAUDE.md changes in 60 days — 1.6/day, with no saturation. Strongest argument against: every cited case is *retrospectively* a missing-constraint story, and the same evidence is also compatible with "constraints exist as soft preferences, agent ignores them, user codifies." The boundary with H-CORRECTION-TAX is genuinely blurry on items 4–5.

**2. Encoded constraints are violated because the encoding is leaky (H-CORRECTION-TAX — alive, narrowed).** Five distinct correction classes recur across sessions separated by days to weeks, in multiple projects, *after* CLAUDE.md encoding. The clearest mechanism is the reactive-bandaid loop: rule added in response to violation → rule itself violates the no-bandaid principle → rule deleted → behavior recurs (`9501a0b0`, `d4565916`, commit `441c6ec`). Memory-system misuse persists across crescent, hologram, and pteraworld despite documentation. Strongest argument against: the red-team's overconfidence finding is correct — the May 13 "Counterweight: don't fake confidence" rule (`7521987c`) actually did suppress that violation class; zero overconfidence corrections appear in the corpus after it landed. Encoding *can* work. The tax is concentrated on constraints that resist clean local encoding (specialcasing-vs-generalization, memory-system-as-default, "is this a bandaid?") rather than uniform cross-session forgetting.

**3. Orchestrator state goes stale, especially across compaction (H-CONTEXT-DRIFT + H-DECOMPOSITION-FAILURE, reformulated — both alive, narrow).** "Long sessions degrade" is dead: `fccf7f65` (641 user messages, 23 compactions, zero pushback) and `a02bc091` (427 messages, 6 compactions, zero) falsify it directly. What survives are two narrower siblings of the same mechanism. Within a session: compaction silently strips high-stakes prior agreements (`db532ce7` "you said -2 was useless, then did your own thing"; `9501a0b0` user diagnosing compaction in real time). Across subagent dispatch: in reincarnate's Phase 1–7 rewrite (`033086a7`, 199 subagents) and HM session (`9e8bf1e4`, 149 subagents), the orchestrator re-dispatches the same logical task because its model of "what prior agents accomplished" decays. The dedicated postmortem subagent `agent-a65afb34f3da35f38` exists only because the orchestrator already knew the rewrite had failed. Clean-parallel baseline (`74176a04`, 443 subagents, 3.2% duplication, no postmortem) confirms that the mechanism activates on shared-mutable-state surfaces, not on dispatch volume. Strongest argument against: in the reincarnate sessions the subagents were sequential, not parallel — so "decomposition failure" is a misnomer; the failure is orchestrator-context decay, the same shape as in-session compaction loss. Both should be understood as the same mechanism at different scopes.

## Cross-hypothesis connections

The three alive hypotheses share a common mechanism: **stateful information that should be invariant across a transition is not.** H-IMPLICIT-CONSTRAINTS is the transition from user-mental-model to new session. H-CORRECTION-TAX is the transition across session boundaries for already-documented preferences. H-CONTEXT-DRIFT/H-DECOMPOSITION-FAILURE is the transition across compaction or across subagent dispatches within a session. CLAUDE.md is the current mechanism for all three and it is leaky at every layer: too small to hold the generator, too large to be reliably attended to, and disconnected from runtime state.

H-PROMPT-SHAPE is dead as causal claim but its reactive-CLAUDE.md-bandaid signal is real — that signal now lives correctly inside H-CORRECTION-TAX as a violation class. H-GOVERNANCE-BREACH is effectively dead at 0.1% true-unilateral rate; its surviving mechanism (over-generalizing user-granted exceptions) is also a H-CORRECTION-TAX subtype. H-MOMENTUM-LOSS is dead: 20-day project gaps are baseline cadence (defocus 17d, private-recipient-b 18d, pteraworld 18d, comfyui 21d) and reincarnate's last session shipped three prerequisite commits, not a deferral. H-CACHE-MASKS-DEGRADATION is the meta-constraint that made the Phase A/B methodology legitimate: aggregate cost and token volume genuinely cannot detect quality changes at 100% cache efficiency, so the investigation correctly relied on cache-independent signals.

## Hypotheses no one tested but the data implies

**H-HARNESS-ORCHESTRATION-FIT.** The single explicit user complaint about Claude Code itself (2026-05-13, `"CLEARLY claude code's harness is not designed for sonnet top level agents at all"`) was logged under H-MODEL-REGRESSION and correctly dismissed there, but its actual content — that the harness assumes a certain class of model in the top-level orchestrator role — was never directly tested. The H-DECOMPOSITION-FAILURE finding (orchestrator-context decay across dispatches) points the same way: the failure mode is at the *orchestrator*, not the workers. This deserves its own hypothesis: *the orchestrator role has weaker context-discipline affordances (compaction, dispatch tracking, subagent state) than the harness assumes*. Test by comparing same-task outcomes with Opus vs Sonnet as orchestrator on coupled subagent work.

**H-DOMAIN-GENERATOR-COMPRESSION.** The investigation conversation surfaced (and the plan flagged) that the user's aesthetic compresses to a small generator. The data is consistent: the cases where CLAUDE.md encoding *worked* (overconfidence rule) are cases where the rule named the failure mode directly; the cases where it failed (no-specialcase, no-bandaid) are cases where the rule states a principle whose application requires running the generator on novel input. No agent tested this directly. Predicted artifact: a generator-corpus (worked examples + counterexamples) would outperform a rule-corpus for the failing classes.

## What we still don't know

- **No baseline for cache-independent quality metrics.** Tool error rates and user-affect counts are reported but never timeseries'd against a counterfactual. We cannot answer "is the ecosystem getting better or worse?" without one.
- **Whether the reactive-bandaid loop is recovering.** The 2026-05-13 commit `441c6ec` *deleted* the reactive-bandaid rule. We have no post-deletion data on whether the behavior recurred or whether the user's discipline alone now holds the line.
- **The orchestrator-context decay rate.** We have re-dispatch evidence but no measurement of *what fraction of orchestrator turns operate on stale subagent-state assumptions*. The investigation could not extract this from the tool.
- **Whether compaction-loss is rare or routine.** Two confirmed cases over 60 days is sparse; users don't always notice when an agreement is lost, so the count is a floor.
- **What the implicit constraint set's saturation curve looks like.** 98 crescent CLAUDE.md commits in 60 days with no slowdown — but no measurement of whether commits-per-violation is rising (saturating) or falling (still mining).
- **Whether the dead hypotheses stay dead.** H-MODEL-REGRESSION was killed on a snapshot. Routine re-checking with cache-independent metrics is the only honest way to keep that verdict current.
