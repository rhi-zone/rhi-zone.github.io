- Investigated the `existence` repo (`~/git/paragarden/existence/`) as prior art: mined 82k tokens of detailed findings on how existence models NPC rewards and learning.

**Key finding from existence review:** existence is a single-player text game, and it has a **critical gap** — its learning system (habit imitation via CART decision trees) is completely decoupled from its reward/valence system (neurochemistry baseline-relative valence + sentiments). Habits learn to predict the player's actions; they don't optimize for reward. No agent in the system pursues reward. The system models *affect and habituation* well (baseline drift, allostasis), but has **no reward-learning agent at all**. This is either a design choice ("the player is the only agent") or an underthought gap.

Committed: findings on existence's architecture (agent output). The session closed with "let's write it down?" — likely intended as a follow-up.

**Observations:** A high-information-density turn despite brevity. The agent's deep structural analysis revealed that existence's reputation for sophisticated reward-modeling doesn't hold under examination. The finding is load-bearing for aeriea's design: if you want NPCs that **learn from reward**, existence is not a usable model — you'd have to build the loop.
